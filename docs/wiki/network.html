Network and DNS

Every app has a LAN name, <app>.local.<domain>. A few also get a public name, <app>.<domain>. Both end at the same Traefik; they differ in how the request gets there. Throughout this page <domain> stands for the real domain, which is not written in the wiki.

Request paths

LAN requestpublic requestDNS lookup
  • LAN: the device asks Pi-hole to resolve <app>.local.<domain>, then speaks HTTPS to Traefik directly. Pi-hole's records live on the Pi-hole itself, not in this repo.
  • Public: the name is a proxied Cloudflare CNAME to the tunnel. cloudflared inside the cluster dials out to Cloudflare and carries requests back in, so the router has no inbound port open.
  • Both paths land on the same Traefik websecure entrypoint and the same IngressRoute. One route can match both hosts.

Names and certificates

Local name

<app>.local.<domain>: LAN only, never published to Cloudflare. Covered by the local-wildcard certificate.

Public name

<app>.<domain>: a Cloudflare CNAME to the tunnel plus an ingress rule. Covered by the public-wildcard certificate.

cert-manager issues both wildcards from Let's Encrypt with DNS-01 challenges, solved through the Cloudflare API token kept in a SOPS secret. DNS-01 needs no inbound port, which is why the LAN wildcard can be trusted even though it is never reachable from outside. Traefik's default TLSStore serves the local wildcard and also offers the public one, so routes only need tls: {}.

DNS inside the cluster

Pods use CoreDNS. A small coredns-custom config adds two rules for the domain:

  • *.local.<domain> and <domain> are forwarded to the node's own resolvers, so pods can reach LAN and public names the same way devices do.
  • Search-path junk such as cluster.local.<domain> and any name with extra labels under the domain answers NXDOMAIN. An empty NOERROR would make musl-based images stop trying their remaining search domains.

Public exposure

Terraform owns the public side. The public_apps map in terraform/cloudflare/terraform.tfvars (git-ignored) lists each public app. For every entry the public-app-ingress module creates one proxied CNAME and one tunnel ingress rule, and the root config appends a catch-all that returns 404. A hostname that is not in the map goes nowhere, even if the Kubernetes route exists.

Legacy routes

Some things on the LAN are not in Kubernetes but should share the same names and certificates: Proxmox, Home Assistant, Pi-hole, Portainer, Plex. Each gets a Service and EndpointSlice pointing at the machine's LAN address, plus an IngressRoute, under infrastructure-configs/legacy-routes. Backends that speak HTTPS with a self-signed certificate use the shared insecure-skip-verify ServersTransport.

Expose an app

LAN only

Add an IngressRoute with a single host. Nothing else is needed.

entryPoints: [websecure]
routes:
  - kind: Rule
    match: Host(`<app>.local.<domain>`)
    services:
      - name: <app>
        port: <port>
tls: {}

Add a record for the name on the Pi-hole if it does not already resolve (REAL, outside this repo).

Public
  1. Add || Host(`<app>.<domain>`) to the route's match.
  2. Add the app to public_apps in terraform.tfvars with its target_url.
  3. Run make apply-cloudflare (REAL).
  4. Verify against a public resolver, not the Pi-hole.
dig +short <app>.<domain> @1.1.1.1
dig +short <app>.<domain> @<pihole-ip>

Gotcha: if the public resolver answers but the Pi-hole returns nothing, the Pi-hole cached the earlier empty answer. LAN devices fail until its DNS cache is flushed. Flush the device's cache or toggle its Wi-Fi after that.
