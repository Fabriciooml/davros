Architecture

Two tools, one boundary. OpenTofu builds what exists before the cluster does (the LXC node, k3s, Cloudflare DNS and tunnel rules). Flux owns everything inside the cluster and reconciles it from this repo. Nothing in kubernetes/ is applied by hand.

Let's Encrypt certificates are issued by cert-manager using DNS-01 against Cloudflare, so no inbound port is needed. Prometheus also scrapes the Proxmox host's exporters (disks, ZFS pool).

Flux order

Three Flux Kustomizations, chained with dependsOn, each decrypting SOPS files with the sops-age secret:

  1. infrastructure: HelmRepositories and HelmReleases (cert-manager, Traefik, monitoring) plus local-path-provisioner and the custom CoreDNS config.
  2. infrastructure-configs: custom resources that only exist once the charts are installed (ClusterIssuers, Certificates, TLSStore, monitoring routes and alerts, legacy routes, image automation).
  3. apps: one directory per workload under kubernetes/apps/.

The split exists because a custom resource cannot apply before its CRD does. Charts first, their resources second, workloads last.

Sonarr and Radarr share one node because their wiring is identical. Prowlarr feeds all three managers; qBittorrent downloads for all three.

Shared folders are host paths under /mnt/pool-data, mounted into pods with hostPath. Because every app sees the same filesystem, imports are hardlinks, not copies:

  • Sonarr, Radarr, Chaptarr: the whole pool.
  • qBittorrent: torrents/.
  • Jellyfin, Plex: media/tv and media/movies. Bazarr: media/.
  • Audiobookshelf: media/audiobooks. CWA: media/books and media/books-ingest, where Chaptarr hardlinks ebooks.

Data services and own apps

Services other apps lean on, in-cluster. samsa and muad-dib (both own apps) use Kafka for events and PostgreSQL for their data. nosso-mapa and comida-di-buteco keep theirs in SQLite files on local-path volumes, so they do not depend on PostgreSQL.

PostgreSQL, Kafka and CouchDB each keep their data on a local-path PVC. Kafka also advertises an external listener for clients outside the cluster.

Secrets

The repo is public. Secret values are committed only as *.sops.yaml, encrypted to an age key. The private key lives outside git; make sops-age-secret delivers it into the flux-system namespace so Flux can decrypt. Lose the key and the committed secrets become unreadable, so back it up. See the runbooks for editing and rotating.

Image updates

Third-party images are pinned by tag and digest, so upgrades are explicit commits. Own apps (samsa, muad-dib, mapa, comida) follow new builds: Flux image automation watches the registry and pushes the new tag to main as a chore(images) commit.

Testing

Every kustomization directory has a tests/test.sh (kubeconform plus yq assertions); Terraform roots have tofu test. make test runs everything without touching real infrastructure.
