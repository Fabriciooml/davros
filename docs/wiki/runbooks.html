Runbooks

Commands marked REAL change real infrastructure and ask for confirmation first.

Bootstrap from scratch
  1. Create the k3s LXC node and install k3s (REAL).
  2. Merge the generated kubeconfig into ~/.kube/config.
  3. Export a GitHub PAT with the repo scope (or put it in .env), then bootstrap Flux (REAL, once per cluster lifetime).
  4. Deliver the SOPS age key into flux-system so Flux can decrypt secrets (REAL). Restore your existing key to AGE_KEY_FILE first: if none exists there, make sops-age-secret generates a NEW key (after a confirm prompt), which will not match .sops.yaml and cannot decrypt the repo's secrets.
  5. Apply DNS and tunnel rules for public apps (REAL).
make apply-cluster
make kubeconfig
export GITHUB_TOKEN=...
make flux-bootstrap
make sops-age-secret
make apply-cloudflare

Or run make bootstrap, which does all of the above in order and still asks to confirm at each real step.

Add an app
  1. Create kubernetes/apps/<app>/ with namespace.yaml, pvc.yaml (storage class local-path), deployment.yaml, service.yaml, ingressroute.yaml and a kustomization.yaml listing them. Copy a similar app such as mealie as the starting point.
  2. Pin the image by tag and digest unless it is one of your own apps that should follow new builds.
  3. LAN route: host <app>.local.<domain> on websecure with tls: {} (default TLS store).
  4. Add a tests/test.sh (kustomize build, kubeconform, yq assertions) like the neighbouring apps.
  5. Add - <app> to kubernetes/apps/kustomization.yaml.
  6. Public app: add a second host <app>.<domain> to the IngressRoute and an entry in the public_apps map in your local terraform/cloudflare/terraform.tfvars (git-ignored; see terraform.tfvars.example). The key is the app name, which becomes the hostname <app>.<domain>, and target_url is the origin the tunnel forwards to, e.g. <app> = { target_url = "<origin-url>" }. Then run make apply-cloudflare (REAL).
  7. Add a description to docs/wiki/data/app-notes.json and run make wiki-catalog.
  8. Run the tests, commit and push. Flux applies it within its 10 minute interval.
make test-kubernetes
make wiki-catalog
git add kubernetes/apps docs/wiki && git commit -m "feat: <app>" && git push
flux reconcile kustomization apps --with-source   # optional, skip the wait
Rotate or edit a SOPS secret

Secrets live in *.sops.yaml files and are encrypted to the age public key in .sops.yaml. Flux decrypts them with the sops-age secret in flux-system.

Change a secret value:

sops kubernetes/apps/<app>/<name>.sops.yaml     # opens in $EDITOR, re-encrypts on save
git commit -am "chore: rotate <name>" && git push

Rotate the age key:

  1. Generate a new keypair with age-keygen -o new.agekey and keep the private file out of the repo (*.agekey is git-ignored).
  2. Add the new public key to .sops.yaml alongside the old one.
  3. Run sops updatekeys on every secret file, with the old key available (e.g. via SOPS_AGE_KEY_FILE) so it can decrypt.
  4. Remove the old recipient from .sops.yaml. This alone changes nothing: the old key stays a recipient of every already-encrypted file until updatekeys is run again.
  5. Run sops updatekeys on every secret file AGAIN so the old key is dropped from the files.
  6. Commit and push .sops.yaml and the re-encrypted files.
  7. Point AGE_KEY_FILE at the new key (default ~/.config/sops/age/keys.txt) and deliver it to the cluster (REAL).
# steps 3 and 5 (run after adding the new key, and again after removing the old one)
find kubernetes -name '*.sops.yaml' -exec sops updatekeys -y {} \;
# step 7
AGE_KEY_FILE=./new.agekey make sops-age-secret
Backup and restore app data

A cron job on the Proxmox host runs k8s-data-backup.sh nightly at 02:45. It rsyncs the app-data disk (/mnt/hd2tb-k8s-appdata) into a dated directory on the backup disk, hardlinking unchanged files against the previous snapshot, and keeps the 7 newest snapshots. Install or re-install it on the host with scripts/proxmox-host/setup-backup-storage.sh then setup-backup-jobs.sh (run as root on the Proxmox host).

Restore one app:

  1. Find the app's volume directory: PVCs use the local-path provisioner, which stores each volume as pvc-<uid>_<namespace>_<claim> under /var/lib/local-pv in the k3s LXC. That path is bind-mounted from /mnt/hd2tb-k8s-appdata/local-pv on the Proxmox host. List them with kubectl get pvc -n <namespace> (the VOLUME column is the pvc-<uid> part).
  2. Pause Flux so it does not scale the app back up, then scale the app down. Note that suspending the apps kustomization pauses reconciliation for EVERY app, so resume it promptly.
  3. On the Proxmox host, rsync the wanted snapshot's copy of that directory over the live one.
  4. Scale back up to the original replica count (1 unless the manifest says otherwise) and resume Flux.

Warning: the rsync below uses --delete and overwrites the live directory, removing anything newer than the snapshot. Confirm <date> and <pvc-dir> are correct and the snapshot directory is not empty. Run the -n dry run first and read its output, and consider copying the live directory aside before the real run.

# --- on the machine with kubectl ---
flux suspend kustomization apps
kubectl -n <namespace> scale deploy/<app> --replicas=0

# --- on the Proxmox host (snapshots: /mnt/hd2tb-backup/k8s-data/<date>/hd2tb-k8s-appdata/local-pv/) ---
ls /mnt/hd2tb-backup/k8s-data/<date>/hd2tb-k8s-appdata/local-pv/<pvc-dir>/
cp -a /mnt/hd2tb-k8s-appdata/local-pv/<pvc-dir> /mnt/hd2tb-k8s-appdata/local-pv/<pvc-dir>.bak   # optional safety copy
rsync -naHAX --numeric-ids --delete -v /mnt/hd2tb-backup/k8s-data/<date>/hd2tb-k8s-appdata/local-pv/<pvc-dir>/ /mnt/hd2tb-k8s-appdata/local-pv/<pvc-dir>/   # dry run
rsync -aHAX --numeric-ids --delete /mnt/hd2tb-backup/k8s-data/<date>/hd2tb-k8s-appdata/local-pv/<pvc-dir>/ /mnt/hd2tb-k8s-appdata/local-pv/<pvc-dir>/

# --- back on the machine with kubectl ---
kubectl -n <namespace> scale deploy/<app> --replicas=<replicas>
flux resume kustomization apps

Check the app's logs after it comes up before trusting the restore. Once the app is verified, delete <pvc-dir>.bak (it is also picked up by the nightly backup).
