# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"davros": single-node homelab. OpenTofu provisions a k3s cluster inside a privileged LXC on one Proxmox host; Flux reconciles everything under `kubernetes/` from this repo (GitHub remote `fabriciooml/davros`, branch `main`). Secrets live in this public repo as SOPS/age-encrypted `*.sops.yaml` files.
## Commands

```
make test                 # all tests, touches no real infra
make test-kubernetes      # runs every kubernetes/**/tests/test.sh (kustomize build + kubeconform + yq asserts)
make test-terraform       # tofu test in every dir with *.tftest.hcl
make test-scripts         # *.test.sh under terraform/ and scripts/
make fmt / validate / init
make wiki-catalog         # regenerate docs/wiki/data/apps.{json,js} from kubernetes/apps (needs PyYAML)
make plan-cluster | plan-cloudflare | plan-vpn   # read-only
```

Single test: `bash kubernetes/apps/<app>/tests/test.sh`, or `cd terraform/<root> && tofu test -filter=tests/<file>.tftest.hcl`.

`apply-*`, `destroy-cluster`, `flux-bootstrap`, `sops-*`, `bootstrap` mutate real infra (each prompts via `make confirm`). `.env` is auto-included by the Makefile (GITHUB_TOKEN, TS_AUTHKEY, etc.); never commit it.

## Architecture

**Flux layering** (`kubernetes/flux-system/*.yaml`): `infrastructure` → `infrastructure-configs` → `apps`, chained with `dependsOn`. All use SOPS decryption via the `sops-age` secret.
- `infrastructure/`: HelmRepository + HelmRelease (cert-manager, traefik, monitoring) plus local-path-provisioner, coredns-custom.
- `infrastructure-configs/`: CRs that need chart CRDs installed first (ClusterIssuers, wildcard Certificates, TLSStore, monitoring alerts/IngressRoutes, `legacy-routes` proxying non-k8s hosts like Plex/Pi-hole/Proxmox, `image-automation`).
- `apps/`: one directory per app, each listed in `kubernetes/apps/kustomization.yaml`. Typical contents: `namespace`, `deployment`, `service`, `pvc`, `ingressroute`, `kustomization.yaml`, `tests/test.sh`. Adding an app means adding it to that list too.

**Every kustomization dir has `tests/test.sh`.** Pattern: `kustomize build`, `kubeconform -strict -ignore-missing-schemas -skip Secret`, then `yq` assertions on deployment, PVC and IngressRoute (look at `kubernetes/apps/comida/tests/test.sh` as the template). Tests encode invariants (e.g. `Recreate` strategy for RWO volumes, expected hosts, image tag); update the test when you change the manifest.

**Hostnames**: LAN-only `<app>.local.<domain>` and public `<name>.<domain>` (both wildcard certs via cert-manager, Traefik IngressRoute `websecure` with `tls: {}`). Public hosts additionally need an entry in `terraform/cloudflare` (`var.public_apps`, using `modules/public-app-ingress`: one DNS record + one tunnel ingress rule) and `make apply-cloudflare`.

**Own-app image automation**: apps with an `image.yaml` (ImageRepository + ImagePolicy in `flux-system` ns, e.g. comida, muad-dib, samsa, mapa) follow a moving tag (`:main`, `imagePullPolicy: Always`). Flux `ImageUpdateAutomation` (commits to `main` as `fluxcdbot`, message `chore(images): ...`) rewrites a digest annotation on the Deployment so the pod rolls. The `# {"$imagepolicy": ...}` setter marker must stay on the same line as the digest value (tests grep for it). Do not pin these apps' images. Expect bot commits on `main`; pull/rebase before pushing.

**Homepage** (`kubernetes/apps/homepage/config/*`): dashboard config files mounted as ConfigMap; widget API keys come from `homepage-secrets.sops.yaml`. Config changes need a pod restart.

**Docs wiki** (`docs/wiki/`): static HTML site; `data/apps.json` is generated by `scripts/gen-wiki-catalog.py` (never opens `*.sops.yaml`, masks the real domain as `<domain>`). Rerun `make wiki-catalog` after app changes.

**Terraform roots**: `k3s-cluster` (LXC + k3s install + kubeconfig fetch scripts), `cloudflare` (DNS/tunnel), `ts-router` (Tailscale subnet-router LXC), `modules/public-app-ingress`. State and `*.tfvars` are gitignored; only `*.tfvars.example` is committed.

**`scripts/proxmox-host/`**: scripts run by hand on the Proxmox host (backup jobs, host/ZFS/SMART metrics for node-exporter, local storage setup), each with a test in `tests/`.

## Working rules (from the user)

- Public repo: never write plaintext secrets or real credentials into tracked files; encrypt with `sops` as `*.sops.yaml`. Don't open/print decrypted secret contents unnecessarily.
- Ask before any action that changes real state (Proxmox, network, DNS, cluster `kubectl apply`, `make apply-*`), even mid-implementation.
- Don't `git commit`. Stop and suggest a message; user commits by hand. Throwaway one-off scripts stay untracked and get deleted after use. `docs/superpowers/` specs/plans stay untracked.
- User's login shell is fish: hand over a script file rather than bash heredocs/`read -s` one-liners for them to run.
